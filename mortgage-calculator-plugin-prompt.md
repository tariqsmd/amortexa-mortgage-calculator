# Prompt: WordPress Gutenberg Block Plugin — "MT Mortgage Calculator"

Use this as a build prompt for an AI coding assistant, or as your own dev checklist.

---

## Objective

Build a modern, standards-compliant WordPress plugin named **"MT Gutenberg Blocks"** that registers a native Gutenberg block allowing users to insert an interactive mortgage calculator anywhere in the block editor. The plugin must follow WordPress Plugin Directory guidelines, WPCS (WordPress Coding Standards), and be built using `@wordpress/scripts` (wp-scripts) with modern block.json-based registration.

---

## 1. Plugin Header & Bootstrap

- Main file: `mt-gutenberg-blocks.php`
- Standard plugin header (Plugin Name, Description, Version, Author, License: GPLv2+, Text Domain, Requires PHP, Requires at least).
- Define a single constant for the text domain and reuse it everywhere — never hardcode the string:
  ```php
  define( 'mtgb_TEXT_DOMAIN', 'mt-gutenberg-blocks' );
  define( 'mtgb_VERSION', '1.0.0' );
  define( 'mtgb_PLUGIN_DIR', plugin_dir_path( __FILE__ ) );
  define( 'mtgb_PLUGIN_URL', plugin_dir_url( __FILE__ ) );
  ```
- Prevent direct access at the top of every PHP file:
  ```php
  if ( ! defined( 'ABSPATH' ) ) { exit; }
  ```
- Use a main plugin class (`class-mt-gutenberg-blocks.php`) with a singleton pattern (`get_instance()`) to avoid global namespace pollution.
- Register activation, deactivation, and uninstall hooks (`register_activation_hook`, `register_deactivation_hook`, and a separate `uninstall.php` file — never handle uninstall logic inline).

## 3. Block Registration (block.json — Modern Standard)

- Use `block.json` metadata (API version 3) registered via `register_block_type()` pointing to the build folder.
- Block should be **dynamic** (server-rendered via `render.php` or a render callback) since mortgage math may need PHP-side validation/filtering — this also allows filters/actions to hook into output.
- Attributes: `loanAmount`, `interestRate`, `loanTerm`, `downPayment`, `currencySymbol`, `showAmortization` (bool), `theme` (string, for style variations).
- Category: `widgets` or a custom category registered via `block_categories_all` filter.
- Supports: `align`, `color`, `spacing` where sensible.

---

## 4. Internationalization (i18n)

- Load text domain via `load_plugin_textdomain()` on `init`, pointing to `/languages`.
- **Never echo raw strings.** Use the esc + translation function family consistently:
  - `esc_html__( 'Loan Amount', mtgb_TEXT_DOMAIN )` for translated + escaped text
  - `esc_html_e( ... )` when echoing directly
  - `esc_attr__()` / `esc_attr_e()` for attribute values
  - `esc_attr_x()` / `_x()` where translator context is needed (e.g., "Term" as noun vs label)
  - `sprintf()` combined with `esc_html__()` for dynamic strings — never concatenate translated fragments
- In JS (block editor side), use `@wordpress/i18n`'s `__()`, `_x()`, `_n()` with the same text domain string, and ensure `wp_set_script_translations()` is called so JS strings are translatable too.

---

## 5. Security

- **Escaping on output, sanitizing on input** — no exceptions:
  - `sanitize_text_field()`, `absint()`, `floatval()` / `sanitize_text_field()` + validation for numeric inputs (loan amount, rate, term)
  - `esc_html()`, `esc_attr()`, `esc_url()` on every dynamic output in `render.php` and admin screens
- **Nonces**:
  - REST API endpoint (if used for server-side calculation) must verify `X-WP-Nonce` via `rest_cookie_check_errors` or `permission_callback` checking `wp_verify_nonce()`.
  - Admin settings form: `wp_nonce_field( 'mtgb_settings_save', 'mtgb_settings_nonce' )` on render, `check_admin_referer( 'mtgb_settings_save', 'mtgb_settings_nonce' )` on save.
  - Pass a localized nonce to JS via `wp_localize_script()` / `wp_add_inline_script()` (`wp_create_nonce( 'wp_rest' )`) if the block calls the REST endpoint client-side.
- **Capability checks**: `current_user_can( 'manage_options' )` before any settings save; `current_user_can( 'edit_posts' )` where relevant for editor-only REST routes.
- Sanitize/validate all block attributes server-side in `render.php` even though the editor already validates — never trust client input.

---

## 6. Actions & Filters (for scalability / extensibility)

Expose hooks so other plugins/themes can extend behavior without modifying core files:

- `do_action( 'mtgb_before_calculator_render', $attributes )` — before block output
- `do_action( 'mtgb_after_calculator_render', $attributes )` — after block output
- `apply_filters( 'mtgb_default_attributes', $defaults )` — let devs change default loan amount/rate/term
- `apply_filters( 'mtgb_calculation_result', $result, $attributes )` — modify computed monthly payment / amortization before output (e.g., for currency conversion plugins)
- `apply_filters( 'mtgb_currency_symbol', $symbol, $attributes )` — for currency/locale plugins
- `apply_filters( 'mtgb_enqueue_assets', $should_enqueue )` — allow disabling default assets if a theme wants to bundle its own
- `do_action( 'mtgb_settings_saved', $settings )` — fired after admin settings update, for logging/integration hooks

---

## 7. Assets & Build Tooling

- Use `@wordpress/scripts` (`wp-scripts start` / `wp-scripts build`) — no manual Webpack config unless extending it via `webpack.config.js` that extends the default.
- Enqueue via `register_block_type()` reading `block.json`'s `editorScript`/`style`/`viewScript` fields — avoid manual `wp_enqueue_script()` duplication where block.json can handle it.
- Only enqueue front-end assets when the block is actually present on the page (`has_block()` check), to avoid loading unused CSS/JS site-wide.
- Version all enqueued assets using `mtgb_VERSION` (or filemtime in dev) for cache busting.

---

## 8. Admin / Settings (optional but recommended for scalability)

- A lightweight settings page under **Settings → MT Mortgage Calculator** using the Settings API (`register_setting`, `add_settings_section`, `add_settings_field`) — not a custom form-only page — so values are sanitized via registered `sanitize_callback`.
- Settings: default currency, default interest rate, decimal precision, enable/disable amortization table.

---

## 9. Calculation Logic

- Core mortgage math (monthly payment formula, amortization schedule) implemented in a pure PHP helper class/function (`includes/helpers.php`) so it's unit-testable and reusable by the REST endpoint, `render.php`, and any future shortcode.
- Mirror the same formula in JS (for live preview in the editor) but treat PHP as the source of truth for front-end rendering.

---

## 10. Standards & Quality

- Follow WPCS; include a `phpcs.xml.dist` ruleset extending `WordPress-Extra` and `WordPress-Docs`.
- PHPDoc blocks on every class/function/hook.
- `readme.txt` in standard WP.org format (Tested up to, Stable tag, Changelog, FAQ).
- Semantic versioning; changelog updated per release.
- No inline styles/scripts — everything enqueued properly.
- Escape late, sanitize early — as a rule for every single output/input point.

---

## Deliverable Expectations

Generate the plugin following this structure exactly, with working PHP class scaffolding, a functional block.json + edit.js/save.js (or render.php) pair, and at least the hooks listed in Section 6 wired in (even if unused internally, they must fire at the right point for third-party extension).
